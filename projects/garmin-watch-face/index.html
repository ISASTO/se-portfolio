01 / Problem

Make the smartwatch less smart.

After moving from an Apple Watch to a Garmin, I wanted the device to feel like a durable instrument—not another attention surface. Existing faces either showed too much or compromised the exact hierarchy I wanted.

My requirements fit in one sentence: show a four-digit 24-hour time, the day and date, and battery percentage, all in high-contrast white on black. There would be no colon, icons, fitness rings, weather, complications, animation, or seconds.

That apparent simplicity made the engineering decisions more visible. On a constrained device, every field has a resource cost, every update has a cadence, and every pixel competes with readability.

02 / Interface

Every element has one job.

The time dominates the face. Context sits above it. Device state sits below it. The layout can be read as a hierarchy before any individual character is parsed.

TIME

Four digits, no colon

Twenty-four-hour time removes AM/PM, and a fixed four-character block creates a stable silhouette. Removing the colon recovers horizontal space for larger numerals.

DATE

Context without competition

The abbreviated weekday and date are small but strongly weighted, centered above the time so they remain easy to find without becoming the first thing seen.

BATTERY

A number, not a metaphor

A percentage is more precise than an icon and needs no interaction. An optional setting allows the percent sign to be hidden while retaining the value.

COLOR

High contrast by default

White on black maximizes clarity and matches the device’s role, while settings expose color choices without complicating the default face.

03 / Rendering

Not everything changes at the same speed.

Treating the entire screen as equally dynamic would be easy—and wasteful. The key optimization was to separate values by how often they can actually change.

1 min Time is the only value that must change on every normal watch-face update.
Periodic Battery is refreshed on a slower schedule instead of being rebuilt without cause.
1 day The displayed date only needs new content when the calendar day changes.

I cache formatted values and reuse them until their source can have changed. Custom text resources are reduced to the fidelity the display requires, keeping the asset footprint controlled. The draw path can then concentrate on placing already-prepared content rather than repeatedly doing formatting work. 

// Simplified rendering strategy
if (minuteChanged)  updateTime();
if (dateChanged)    updateDate();
if (batteryIsDue)   updateBattery();

draw(cachedDate, cachedTime, cachedBattery);
04 / Constraints

Device work makes hidden costs concrete.

Connect IQ’s resource system, simulator, packaging flow, and device lifecycle are unlike a browser runtime. Fonts need to be prepared for the target display. Geometry must survive a fixed circular canvas. Code that looks harmless on a desktop deserves scrutiny when it will execute all day on a battery-powered device.

The difficult parts were small and exact

  • Building and loading custom font resources that rendered consistently on-device.
  • Balancing the maximum readable time size against a round display’s narrowing edges.
  • Separating configurable colors from the simplest possible default appearance.
  • Testing the packaged face on the physical Forerunner rather than trusting the simulator alone.
  • Optimizing expected costs without pretending that an unmeasured change guarantees battery savings.
Constraint did not shrink the design problem. It forced every element—and every update—to justify itself.
05 / Outcome

A personal tool that disappears into use.

The finished face runs on my daily watch and gives me exactly the information I reach for, with no notification-like visual noise and no interaction required.

This project made me more precise about the difference between optimization and measurement. I can show that the implementation avoids unnecessary computation; a controlled long-duration comparison against a stock face is the next step before claiming a quantified battery improvement.

LESSON 01

Update frequency is architecture

Data with different lifetimes should not be formatted, cached, or refreshed as if it were identical.

LESSON 02

Omission is an interface decision

Removing information is valuable when the remaining hierarchy better matches the device’s purpose.

LESSON 03

Hardware is the final environment

A simulator speeds iteration, but visibility, spacing, and resource behavior must survive the actual device.

LESSON 04

Measure before claiming

Reasonable performance decisions are not the same thing as evidence of an end-to-end battery result.
